## Problem Statement

Monorepo READMEs show folder trees or dry dependency graphs. Contributors (and star-hunters) don’t *feel* the system. Status quo: Mermaid, Nx/turbo graph dumps, DepsView/Flare-style live import heatmaps, or AI “repo maps” (RepoGraph, GitAtlas). Wanted: a **shareable subway metaphor** — packages as stations, workspace deps as rails, **turbo tasks as trains that move** — optimized for README GIF / `npx` showcase first, daily dashboard second.

Rejected this session / earlier: Korean skill mini-packs (k-skill owns), agent pets (saturated), live AI touch heatmaps (DepsView/Flare), conversational skill makers (skillify/gstack), `agent-gate` (useful but deprioritized for viral visual OSS).

## What Makes This Cool

`npx turbometro` → real pnpm/turbo graph as a **metro map** with **rails + animated trains** (replayable in v0.1). Screenshot/GIF drops straight into README. Later: trains = live turbo/CI runs.

Slogan: **Your monorepo as a subway — trains run when turbo does.**

## Constraints

- **Name:** `turbometro` (locked; npm 404 at design time; unrelated `TurboMap` SLAM repos exist — different domain).
- **Audience (v0.1):** OSS README / showcase wow. Daily team dashboard = roadmap.
- **Data (v0.1):** **pnpm workspace + turbo** only. `pnpm-workspace.yaml` + root/workspace `package.json` deps + `turbo.json` tasks.
- **Trains mean:** running / replayed **turbo tasks** (build/test/lint…), not agent file-touch, not random decoration-only (decoration-only rejected).
- **v0.1 motion:** **replayable** trains (scripted or recorded from a turbo run) so demos/GIFs work without a live pipeline. Live process attach = v0.2+.
- **Not in v0.1:** npm/yarn-only workspaces, language-agnostic import graphs, manual YAML as primary source, real-time CI websocket, agent activity overlay.
- **Secrets:** none. Local filesystem + generated static HTML/SVG/GIF.
- **Distribution:** GitHub under **`scs0209/turbometro`** (all commits/remotes/publish — not ayaan0209). MIT. CLI: `npx turbometro` (or `pnpm dlx`). bin-ready in v0.1; npm CI publish may follow tag.

## Premises

1. People want a **moving subway map in the README** more than a daily ops tool (confirmed). Completeness of need is viral/share, not desperate weekly pain.
2. v0.1 = **real package graph** + **replayable trains** beats static-only or live-only.
3. Differentiation vs nf-metro / api-subway / RepoGraph: **JS monorepo packages + turbo task trains**, not Nextflow/API routes/file trees.
4. Narrow wedge: one stack (pnpm+turbo) done beautifully > universal graph soup.

## Approaches Considered

### Approach A: Static metro SVG only
Packages + edges, no trains. Fast, but breaks the “철로+전철” promise. **Rejected for v0.1.**

### Approach B: Real graph + replayable trains (demo player)
Parse pnpm/turbo → layout metro lines → play a timeline of task events (fixture or `turbo` log). GIF-friendly. **Chosen for v0.1.**

### Approach C: Live turbo/CI overlay from day one
Highest fidelity, slowest first ship, weak cold-start for README stars. **Deferred to v0.2+.**

### Chosen path
**B now, C later.**

## Recommended Approach

### Mental model

| Metro | Repo |
|-------|------|
| Station | Workspace package (`apps/*`, `packages/*`) |
| Line / rail | Dependency edge and/or task pipeline edge |
| Train | A turbo task (or pipeline) moving along packages it touches |
| Transfer | Shared package depended on by multiple apps |

### v0.1 CLI sketch

```bash
npx turbometro                 # cwd = monorepo root → write dist/metro.html
npx turbometro --demo          # built-in sample monorepo timeline
npx turbometro --replay run.json
npx turbometro --gif           # optional: headless capture for README (post-MVP ok if HTML+manual GIF first)
```

### Graph intake (v0.1)

1. Require `pnpm-workspace.yaml` + root `package.json`. Else exit with clear error (suggest roadmap stacks).
2. Enumerate workspace packages; edges from `dependencies` / `devDependencies` that resolve to workspace protocol (`workspace:*` or matching names).
3. Read `turbo.json` `tasks` for line colors / legend (task name → line identity).
4. Layout: orthogonal “subway” routing (prefer existing layout lib or simple force+orthogonalize — eng detail in `/plan-eng-review`). Aesthetic > perfect geographic accuracy.

### Train replay (v0.1)

- Input: JSON timeline `{ events: [{ t, task, package, status }] }` **or** generate a plausible demo from graph topology for `--demo`.
- Animation: SVG/CSS or canvas trains follow rail paths; status colors (running / pass / fail).
- Loop + scrub for GIF recording.
- Document: “v0.1 trains are replay; live turbo comes next.”

### Launch checklist

1. README with slogan, GIF of trains on a sample monorepo, `npx` one-liner.
2. Fixture monorepo under `fixtures/mini-mono` (few packages, turbo.json).
3. Open issues: live turbo attach; npm/yarn; CI badge embed; GIF auto-export.
4. Tag `v0.1.0`.
